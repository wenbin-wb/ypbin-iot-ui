# 平台级导航原型（顶部大模块 + 左侧二级）

> 单文件、离线、零外链的 HTML 原型，用来确认**平台的模块划分与导航骨架**：
> 顶部 1 个首页 + 4 个大模块，点模块切换左侧二级菜单，路由走 `location.hash`。
>
> 文件：`docs/ux-mock/platform-nav.html`（本文件同目录）
> 默认打开：`#/workbench`（工作台）

## 1. 它是什么 / 不是什么

**是**：一张可点击的信息架构（IA）图纸。回答「平台该怎么分模块、每个页面归到哪个模块的哪个分组」。

**不是**：

- 不是生产代码，**不参与任何构建**（`docs/.vitepress/config/shared.mts` 里 `srcDir: 'src'`，本目录在其之外，VitePress 不会扫描到）；
- **不对接任何接口**，全部数据都是文件顶部 `DB` 常量里的硬编码假数据；
- 没有登录/退出、没有真实搜索、没有真实列表查询：工具条与行内按钮点击只弹一条「原型占位」提示；
- 页面里出现的口径标记只有三种：`复用` / `新增` / `缺接口`（含义见第 5 节），且与既定事实清单逐条一致。

## 2. 怎么打开

```bash
# 方式一：桌面环境直接双击
xdg-open docs/ux-mock/platform-nav.html      # Linux
open docs/ux-mock/platform-nav.html          # macOS

# 方式二：浏览器地址栏直接打开本地文件
#   file:///<仓库路径>/ypbin-iot-ui/docs/ux-mock/platform-nav.html
```

不需要本地服务器，不需要联网，`file://` 下 hash 路由、前进/后退、刷新都正常。

### 离线保证（零外链）

CSS/JS 全部内联；**不含** `<link>`、`<img>`、`<iframe>`、`<script src=`、外部字体；图标只用内联 SVG 与 Unicode 字符；`platform-nav.html` 内**不含字符串 `http`**（连 `xmlns="…w3.org…"` 都没有——内联 SVG 在 HTML 文档里由解析器自动归入 SVG 命名空间，无需声明）。

### 可复现的自证命令

```bash
cd ypbin-iot-ui
grep -c 'http' docs/ux-mock/platform-nav.html   # 期望输出 0
grep -nE '<(script|link|img|iframe)' docs/ux-mock/platform-nav.html
```

本机实测输出：

```
$ grep -c 'http' docs/ux-mock/platform-nav.html
0
$ echo $?
1
```

> ⚠️ 读法提醒：`grep -c` 在匹配数为 0 时**退出码是 1**，这是 grep 的正常行为，不是失败。别把它接在 `&&` 后面，否则后面的命令不会执行。

```
$ grep -nE '<(script|link|img|iframe)[^>]*>' docs/ux-mock/platform-nav.html
273:<script>
```

第二条件命令只会命中**一行**：唯一的内联脚本开标签 `<script>`（**没有 `src` 属性**）。除此之外没有任何 `link` / `img` / `iframe`。若要严格只看外链，可加一条更窄的检查：

```bash
grep -nE '<(script|link|img|iframe)[^>]*(src|href)=' docs/ux-mock/platform-nav.html   # 期望无输出
```

> 注意：本 README 为了给出自证命令，自身也必然含若干次字符串 `http`（命令文本本身就带着它，自指计数会随说明文字变化）。**零外链这条验收要求只针对 `platform-nav.html`：那里是 0 次。**

### 语法粗检

```bash
node -e "const s=require('fs').readFileSync('docs/ux-mock/platform-nav.html','utf8');const m=s.match(/<script[^>]*>([\s\S]*)<\/script>/);new Function(m[1]);console.log('JS 语法 OK')"
# 实测输出：JS 语法 OK
```

（`new Function` 只做**解析**，不执行脚本体，因此不会碰 `document`/`location` 等浏览器 API。整个文件只有一个 `<script>` 块，正则不会跨块误截。）

## 5. 来源标记的含义

| 标记 | 含义 | 本原型中的分布 |
| --- | --- | --- |
| `复用` | 后端接口与权限码**已存在**（含已有前端页面），差的是前端形态或接入 | 基础管理 15 项、知识与 AI 7 项、运维与监控 8 项、物联网 7 项（产品与物模型 / 设备台账 / 设备分组 / 维护窗口 / 时序查询 / 设备影子 / 租户接入台账） |
| `新增` | 后端能力具备，**需要新增前端页面** | 物联网 3 项：接入向导、产品详情、设备详情 |
| `缺接口` | 后端**完全无此能力**（或聚合/批量端点缺失），需先补后端 | 物联网 6 项：产品模板中心、健康总览、断档与可用率（批量端点）、事件与告警（无事件模型）、在线调试（下行通道不存在）、数据保留与清理 |

标记同时出现在**左侧菜单项右侧的小标签**（鼠标悬停有说明 tooltip）与**占位页正文**中；物联网「设备台账」页的黄色标注框还额外有一行「来源」，说明它是复用页。

## 7. 浏览器要求

- **file:// 直接打开即可**，不需要本地服务器。
- 需要支持：CSS Grid、`Element.closest`、`const/let`、`Array.prototype.map/forEach/filter`。
  实务上 **Chrome/Edge ≥ 90、Firefox ≥ 90、Safari ≥ 15** 均可（注意脚本中**没有使用**箭头函数与模板字符串，因此兼容面比上述版本要求更宽）。
- 宽度自适应：窗口 **< 1100px** 时左侧二级菜单收成 56px 窄条（分组标题变成 `···` 分隔符，菜单项只显示首字方块）。**没有做移动端抽屉**。
- 路由基于 `location.hash`：`#/iot/devices`、`#/admin/users`、`#/workbench` 等；刷新停当前页，前进/后退可用。

## 8. 本原型的已知取舍（如实列出）

1. **工作台的左侧菜单是补的**：规格只定义了 4 个业务模块的二级菜单，没说工作台（首页）左侧放什么。为满足「当前项高亮」，工作台左侧渲染一个「模块导航」分组（首项为工作台自身，可高亮），其余 4 项跳到各模块首页。
2. **知识与 AI 的菜单是平铺的**：规格里该模块的二级项没有分组括号，因此**不给它编分组标题**；基础管理里的「文件管理」同理，按规格作为不带分组的独立单项渲染（这两个模块因此没有可折叠的分组标题，分组折叠只存在于有分组的模块）。
3. **按钮一律不接逻辑**：搜索框、铃铛、平台管理员下拉、`新建 / 查看 / 编辑 / 重置密码 / 导出` 等点击后只弹一条深色 toast「原型占位：…未接入逻辑」。这是为了让「可点」不至于变成「点了没反应」，属于原型交互约定，不是功能实现。
