## 3. 未解决的缺陷（重构优先项）

### 3.1 设备悬停高亮不生效（用户明确要求「悬浮就亮，不是点击」）

- 现状：**只有点击**才高亮；鼠标移动不点亮。
- 原因：`device-anchor-layer.ts` 命中依赖「模型节点包围盒投影矩形」，园区场景里设备只有
  几个像素，指针很难落进矩形。
- 建议：改为「屏幕距离最近设备 + 阈值」的软命中（像地图 POI 吸附），阈值按设备屏幕尺寸缩放；
  并把 hover 高亮与选中高亮分成两档（悬停弱、选中强）。

### 3.2 「点 A 亮 B」

- 现状：吸附兜底取「离指针最近的设备」，指针落在两台之间时会选错。
- 建议：吸附只在「指针落在设备投影区域内或外扩 ≤8px」时生效；否则不选中。
  同时用 `raycaster.intersectObject` 的**最近交点对象**优先反查点位（目前
  `findPointByHit` 只按名字匹配，命中父节点名时可能错配到同名前缀的其它设备）。

### 3.3 用户侧仍观察到「楼和地面在闪」

- 我方实测（本机 Chromium，软件渲染）：静置/旋转后逐帧像素比对 **0 变化**；
  但用户在真实设备上仍能看到闪烁 —— **说明复现环境差异**（显卡/浏览器/驱动）。
- 已修的三处（可能不是全部原因）：
  1. 环境地面与模型自带地面同高 → z-fighting（地面下沉 1.5% + polygonOffset + 全哑光）；
  2. 阴影 `bias = shadowBias × 模型尺寸`（380m 园区 bias 达 -0.19m）→ 改为世界单位常量；
  3. 阴影相机 far 与主相机 near/far 跨度过大 → 收紧。
- **重构时必须先拿到**：用户设备的 `chrome://gpu`（Graphics Feature Status）+ 录屏。
  若为 SwiftShader/软件渲染，需单独跑一遍三角形/绘制调用统计（`renderer.info`），
  排查是否 `LogarithmicDepthBuffer` 缺失、或后处理 RT 深度精度不足（`EffectComposer`
  默认 `HalfFloatType`，`OutputPass` 前后精度链需核对）。
